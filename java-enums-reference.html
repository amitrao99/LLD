1. Declaration & Basics

Simplest Form

public enum Status {
    PENDING, APPROVED, REJECTED, CANCELLED
}

Where Enums Can Be Declared

// 1. Top-level (own file: Status.java)
public enum Status { ACTIVE, INACTIVE }

// 2. Nested inside a class
public class Order {
    public enum Status { PENDING, SHIPPED, DELIVERED }
}

// 3. Nested inside an interface
public interface Payment {
    enum Type { CREDIT, DEBIT, UPI }  // implicitly public static
}
What the Compiler Does

Every enum implicitly extends java.lang.Enum<E>. You cannot extend another class. Each constant is a public static final instance of the enum type, instantiated once when the class loads.

Access Modifiers on Constants

Enum constants are always implicitly public static final. You cannot change this. The enum type itself can be public, package-private, protected, or private (if nested).

2. Fields & Constructors

Adding Fields

public enum HttpStatus {
    OK(200, "Success"),
    NOT_FOUND(404, "Not Found"),
    INTERNAL_ERROR(500, "Internal Server Error");

    private final int code;
    private final String message;

    // Constructor MUST be private or package-private
    HttpStatus(int code, String message) {
        this.code = code;
        this.message = message;
    }

    public int getCode() { return code; }
    public String getMessage() { return message; }
}
Constructor Rules

Enum constructors are never public or protected. They're called automatically when the enum class loads. You cannot call new HttpStatus() from outside.

Initialization Order

public enum Demo {
    A, B, C;
    
    static { System.out.println("Static block"); }
    { System.out.println("Instance block"); }
    Demo() { System.out.println("Constructor"); }
}
// Output when class loads:
// Instance block, Constructor (for A)
// Instance block, Constructor (for B)
// Instance block, Constructor (for C)

3. Methods in Enums

Instance Methods

public enum Size {
    SMALL(1), MEDIUM(2), LARGE(3);
    
    private final int multiplier;
    Size(int m) { this.multiplier = m; }

    public double calculatePrice(double basePrice) {
        return basePrice * multiplier;
    }
    
    public boolean isLargerThan(Size other) {
        return this.multiplier > other.multiplier;
    }
}

// Usage
double price = Size.LARGE.calculatePrice(10.0);  // 30.0

Abstract Methods (Constant-Specific Behavior)

Interview Favorite Each constant provides its own implementation.

public enum Operation {
    ADD {
        @Override
        public double apply(double a, double b) { return a + b; }
    },
    SUBTRACT {
        @Override
        public double apply(double a, double b) { return a - b; }
    },
    MULTIPLY {
        @Override
        public double apply(double a, double b) { return a * b; }
    },
    DIVIDE {
        @Override
        public double apply(double a, double b) { 
            if (b == 0) throw new ArithmeticException("Division by zero");
            return a / b; 
        }
    };

    public abstract double apply(double a, double b);
}

// Usage
double result = Operation.ADD.apply(5, 3);  // 8.0

Multiple Overridden Methods per Enum Constant

Each enum constant can override multiple methods inside the same constant-specific class body. The comma , separates enum constants — not methods.

Key Rule

An enum constant gets one anonymous class body. Inside that body, you can override any number of methods, written sequentially — no commas. 

public enum Operation {
    ADD {
        @Override
        public double apply(double a, double b) {
            return a + b;
        }

        @Override
        public String symbol() {
            return "+";
        }

        @Override
        public boolean isSafe(double a, double b) {
            return true;
        }
    },

    DIVIDE {
        @Override
        public double apply(double a, double b) {
            if (b == 0)
                throw new ArithmeticException("Division by zero");
            return a / b;
        }

        @Override
        public String symbol() {
            return "/";
        }

        @Override
        public boolean isSafe(double a, double b) {
            return b != 0;
        }
    };

    // Abstract methods that constants may override
    public abstract double apply(double a, double b);

    // Default methods (optional override)
    public String symbol() {
        return name();
    }

    public boolean isSafe(double a, double b) {
        return true;
    }
}
Common Mistake

You cannot do this: ADD { ... }, { ... }
A comma ends the enum constant — it does not add another method block.

Static Methods & Lookup Pattern

Interview Favorite Custom lookup by field value.

public enum ErrorCode {
    NOT_FOUND(404),
    UNAUTHORIZED(401),
    FORBIDDEN(403),
    SERVER_ERROR(500);

    private final int code;
    ErrorCode(int code) { this.code = code; }

    // Pre-built lookup map for O(1) access
    private static final Map<Integer, ErrorCode> BY_CODE = 
        Arrays.stream(values())
              .collect(Collectors.toMap(e -> e.code, e -> e));

    public static Optional<ErrorCode> fromCode(int code) {
        return Optional.ofNullable(BY_CODE.get(code));
    }
}

// Usage
ErrorCode err = ErrorCode.fromCode(404).orElseThrow();

Override with Default + Specific

public enum Day {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY,
    SATURDAY {
        @Override
        public boolean isWeekend() { return true; }
    },
    SUNDAY {
        @Override
        public boolean isWeekend() { return true; }
    };

    // Default implementation
    public boolean isWeekend() { return false; }
}

4. Built-in Methods

Method Returns Notes
name() String Exact constant name as declared. Final, cannot override.
toString() String Same as name() by default. Can be overridden.
ordinal() int Zero-based position. Don't persist this!
values() E[] Compiler-generated. Returns fresh array copy each call.
valueOf(String) E Exact match required. Throws IllegalArgumentException.
compareTo(E) int Compares by ordinal. Final, cannot override.
getDeclaringClass() Class<E> Returns the enum type (useful with constant-specific classes). 
public enum Status { PENDING, ACTIVE, CLOSED }

Status s = Status.ACTIVE;

s.name()       // "ACTIVE"
s.toString()   // "ACTIVE" (override for custom)
s.ordinal()    // 1

Status.values()            // [PENDING, ACTIVE, CLOSED]
Status.valueOf("ACTIVE")   // Status.ACTIVE
Status.valueOf("active")   // IllegalArgumentException!

Status.ACTIVE.compareTo(Status.PENDING)  // > 0 (ACTIVE comes after)
Never Persist ordinal()

If you save ordinal to a database and later reorder or insert enum constants, your data becomes corrupted. Always persist name() or a dedicated field.

Safe valueOf Alternative

public static <E extends Enum<E>> Optional<E> safeValueOf(
        Class<E> enumClass, String name) {
    try {
        return Optional.of(Enum.valueOf(enumClass, name));
    } catch (IllegalArgumentException e) {
        return Optional.empty();
    }
}

5. Core Behavior & Guarantees

Identity Comparison

Use == instead of equals(). Enum constants are singletons. == is null-safe and faster.

if (status == Status.ACTIVE)

Serialization Safe

Enums handle serialization specially. Only name() is serialized. Deserialization uses valueOf(). Singleton guarantee preserved.

Thread Safe

Enum constants are initialized in a thread-safe manner by the JVM class loader. No additional synchronization needed for constant access.

Cannot Be Cloned

clone() is final and throws CloneNotSupportedException. This maintains the singleton property.

Switch Statement Behavior

Status status = getStatus();

// Classic switch
switch (status) {
    case PENDING:   // NOT Status.PENDING
        handlePending();
        break;
    case ACTIVE:
        handleActive();
        break;
    default:
        handleOther();
}

// Modern switch expression (Java 14+)
String message = switch (status) {
    case PENDING -> "Waiting for approval";
    case ACTIVE -> "Currently active";
    case CLOSED -> "No longer active";
};

// Compiler warns if cases not exhaustive (no default needed if all covered)
Switch Expression Exhaustiveness

With switch expressions, the compiler enforces that all enum constants are handled. If you add a new constant, all switches break at compile time—exactly what you want.

6. Implementing Interfaces

Enums can implement any number of interfaces. This is the primary way to achieve polymorphism since they can't extend classes.

public interface Describable {
    String getDescription();
    String getCode();
}

public interface Discountable {
    double getDiscountPercent();
}

public enum MembershipTier implements Describable, Discountable {
    BRONZE("BR", "Basic membership", 5.0),
    SILVER("SV", "Silver membership", 10.0),
    GOLD("GD", "Gold membership", 15.0),
    PLATINUM("PT", "Platinum membership", 25.0);

    private final String code;
    private final String description;
    private final double discountPercent;

    MembershipTier(String code, String desc, double discount) {
        this.code = code;
        this.description = desc;
        this.discountPercent = discount;
    }

    @Override public String getCode() { return code; }
    @Override public String getDescription() { return description; }
    @Override public double getDiscountPercent() { return discountPercent; }
}

// Now you can use polymorphically
public void printInfo(Describable item) {
    System.out.println(item.getCode() + ": " + item.getDescription());
}

Functional Interface Implementation

public enum StringTransform implements Function<String, String> {
    UPPER {
        @Override
        public String apply(String s) { return s.toUpperCase(); }
    },
    LOWER {
        @Override
        public String apply(String s) { return s.toLowerCase(); }
    },
    REVERSE {
        @Override
        public String apply(String s) { 
            return new StringBuilder(s).reverse().toString(); 
        }
    }
}

// Usage with streams
List<String> results = names.stream()
    .map(StringTransform.UPPER)
    .collect(Collectors.toList());

7. EnumSet & EnumMap

Interview Favorite Highly optimized collections specifically for enums.

EnumSet

Internally uses bit vectors. Extremely fast and memory efficient. All operations are O(1).

public enum Permission {
    READ, WRITE, EXECUTE, DELETE, ADMIN
}

// Creation methods
EnumSet<Permission> none = EnumSet.noneOf(Permission.class);
EnumSet<Permission> all = EnumSet.allOf(Permission.class);
EnumSet<Permission> some = EnumSet.of(Permission.READ, Permission.WRITE);
EnumSet<Permission> range = EnumSet.range(Permission.READ, Permission.EXECUTE);
EnumSet<Permission> complement = EnumSet.complementOf(some); // EXECUTE, DELETE, ADMIN

// Operations
some.add(Permission.DELETE);
some.remove(Permission.READ);
boolean canWrite = some.contains(Permission.WRITE);
boolean hasAll = some.containsAll(EnumSet.of(Permission.READ, Permission.WRITE));

EnumSet Use Case: Role Permissions

public class Role {
    private final String name;
    private final EnumSet<Permission> permissions;

    public Role(String name, Permission... perms) {
        this.name = name;
        this.permissions = perms.length == 0 
            ? EnumSet.noneOf(Permission.class)
            : EnumSet.copyOf(Arrays.asList(perms));
    }

    public boolean hasPermission(Permission p) {
        return permissions.contains(p);
    }

    public boolean hasAllPermissions(EnumSet<Permission> required) {
        return permissions.containsAll(required);
    }
}

// Usage
Role admin = new Role("Admin", Permission.values());
Role viewer = new Role("Viewer", Permission.READ);

EnumMap

Array-backed map with enum keys. Maintains natural enum order. Much faster than HashMap for enum keys. 

public enum Day { MON, TUE, WED, THU, FRI, SAT, SUN }

EnumMap<Day, String> schedule = new EnumMap<>(Day.class);
schedule.put(Day.MON, "Team standup");
schedule.put(Day.WED, "Sprint planning");
schedule.put(Day.FRI, "Retrospective");

// Iteration is in enum declaration order
schedule.forEach((day, event) -> 
    System.out.println(day + ": " + event));

EnumMap Use Case: State Transitions

public enum OrderState { NEW, CONFIRMED, SHIPPED, DELIVERED, CANCELLED }

EnumMap<OrderState, EnumSet<OrderState>> transitions = new EnumMap<>(OrderState.class);

transitions.put(OrderState.NEW, 
    EnumSet.of(OrderState.CONFIRMED, OrderState.CANCELLED));
transitions.put(OrderState.CONFIRMED, 
    EnumSet.of(OrderState.SHIPPED, OrderState.CANCELLED));
transitions.put(OrderState.SHIPPED, 
    EnumSet.of(OrderState.DELIVERED));
transitions.put(OrderState.DELIVERED, EnumSet.noneOf(OrderState.class));
transitions.put(OrderState.CANCELLED, EnumSet.noneOf(OrderState.class));

public boolean canTransition(OrderState from, OrderState to) {
    return transitions.get(from).contains(to);
}

8. Enum-Based Singleton

Design Pattern Interview Favorite The recommended way to implement singletons in Java.

public enum DatabaseConnection {
    INSTANCE;

    private Connection connection;

    DatabaseConnection() {
        // Initialize on first access to enum
        try {
            this.connection = DriverManager.getConnection(
                "jdbc:mysql://localhost/db", "user", "pass"
            );
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
    }

    public Connection getConnection() {
        return connection;
    }

    public void executeQuery(String sql) {
        // ... implementation
    }
}

// Usage
Connection conn = DatabaseConnection.INSTANCE.getConnection();
DatabaseConnection.INSTANCE.executeQuery("SELECT * FROM users");

Concern Traditional Singleton Enum Singleton

9. State Machines

Design Pattern LLD Essential

Self-Contained State Machine

public enum TrafficLight {
    RED {
        @Override
        public TrafficLight next() { return GREEN; }
        @Override
        public Duration getDuration() { return Duration.ofSeconds(30); }
    },
    GREEN {
        @Override
        public TrafficLight next() { return YELLOW; }
        @Override
        public Duration getDuration() { return Duration.ofSeconds(45); }
    },
    YELLOW {
        @Override
        public TrafficLight next() { return RED; }
        @Override
        public Duration getDuration() { return Duration.ofSeconds(5); }
    };

    public abstract TrafficLight next();
    public abstract Duration getDuration();
}

Complex State Machine with Events

public enum DocumentState {
    DRAFT {
        @Override
        public DocumentState onEvent(Event event) {
            return switch (event) {
                case SUBMIT -> PENDING_REVIEW;
                case DELETE -> DELETED;
                default -> this;
            };
        }
    },
    PENDING_REVIEW {
        @Override
        public DocumentState onEvent(Event event) {
            return switch (event) {
                case APPROVE -> APPROVED;
                case REJECT -> DRAFT;
                case DELETE -> DELETED;
                default -> this;
            };
        }
    },
    APPROVED {
        @Override
        public DocumentState onEvent(Event event) {
            return switch (event) {
                case PUBLISH -> PUBLISHED;
                case ARCHIVE -> ARCHIVED;
                default -> this;
            };
        }
    },
    PUBLISHED {
        @Override
        public DocumentState onEvent(Event event) {
            return event == Event.ARCHIVE ? ARCHIVED : this;
        }
    },
    ARCHIVED {
        @Override
        public DocumentState onEvent(Event event) {
            return event == Event.RESTORE ? DRAFT : this;
        }
    },
    DELETED {
        @Override
        public DocumentState onEvent(Event event) {
            return this; // Terminal state
        }
    };

    public enum Event { SUBMIT, APPROVE, REJECT, PUBLISH, ARCHIVE, RESTORE, DELETE }

    public abstract DocumentState onEvent(Event event);
    
    public boolean isTerminal() {
        return this == DELETED;
    }
}

// Usage
DocumentState state = DocumentState.DRAFT;
state = state.onEvent(DocumentState.Event.SUBMIT);  // PENDING_REVIEW
state = state.onEvent(DocumentState.Event.APPROVE);  // APPROVED

10. Strategy Pattern

Design Pattern

Payment Processing Example

public enum PaymentMethod {
    CREDIT_CARD {
        @Override
        public PaymentResult process(PaymentRequest request) {
            // Validate card, call payment gateway
            return processCreditCard(request);
        }
        
        @Override
        public double calculateFee(double amount) {
            return amount * 0.029 + 0.30; // 2.9% + $0.30
        }
    },
    PAYPAL {
        @Override
        public PaymentResult process(PaymentRequest request) {
            return processPayPal(request);
        }
        
        @Override
        public double calculateFee(double amount) {
            return amount * 0.034 + 0.30; // 3.4% + $0.30
        }
    },
    BANK_TRANSFER {
        @Override
        public PaymentResult process(PaymentRequest request) {
            return processBankTransfer(request);
        }
        
        @Override
        public double calculateFee(double amount) {
            return 0.25; // Flat fee
        }
    };

    public abstract PaymentResult process(PaymentRequest request);
    public abstract double calculateFee(double amount);
    
    // Private helper methods would go here
    private static PaymentResult processCreditCard(PaymentRequest r) { /*...*/ }
    private static PaymentResult processPayPal(PaymentRequest r) { /*...*/ }
    private static PaymentResult processBankTransfer(PaymentRequest r) { /*...*/ }
}

Validation Strategy

public enum ValidationRule {
    NOT_NULL {
        @Override
        public boolean validate(Object value) {
            return value != null;
        }
    },
    NOT_EMPTY {
        @Override
        public boolean validate(Object value) {
            if (value == null) return false;
            if (value instanceof String s) return !s.isEmpty();
            if (value instanceof Collection c) return !c.isEmpty();
            return true;
        }
    },
    POSITIVE {
        @Override
        public boolean validate(Object value) {
            if (value instanceof Number n) {
                return n.doubleValue() > 0;
            }
            return false;
        }
    };

    public abstract boolean validate(Object value);
    
    public static boolean validateAll(Object value, ValidationRule... rules) {
        return Arrays.stream(rules).allMatch(r -> r.validate(value));
    }
}

// Usage
boolean valid = ValidationRule.validateAll(amount, 
    ValidationRule.NOT_NULL, ValidationRule.POSITIVE);

11. Gotchas & Pitfalls

Gotcha Static Field Initialization Order

Enum constants are initialized before static fields. You cannot reference static fields from constructors.

public enum Broken {
    A, B, C;
    
    private static int counter = 0;  // NOT initialized when A, B, C are created!
    private final int id;
    
    Broken() {
        this.id = counter++;  // counter is still 0 for all!
    }
}

// Solution: Use ordinal() or compute in instance method
public enum Fixed {
    A, B, C;
    
    public int getId() {
        return ordinal(); // Works fine
    }
}
Gotcha values() Creates New Array

Every call to values() creates a new array. Cache it for performance-critical code.

// Bad: Creates new array each iteration
for (int i = 0; i < 1000000; i++) {
    for (Status s : Status.values()) { ... }
}

// Good: Cache the array
private static final Status[] VALUES = Status.values();
for (int i = 0; i < 1000000; i++) {
    for (Status s : VALUES) { ... }
}
Gotcha Mutable Fields

Nothing prevents you from having mutable fields, but it violates enum semantics.

// BAD: Mutable enum state
public enum BadEnum {
    INSTANCE;
    private List<String> items = new ArrayList<>();  // Mutable!
    public void addItem(String s) { items.add(s); }  // Thread-unsafe!
}

// GOOD: Immutable or thread-safe
public enum GoodEnum {
    INSTANCE;
    private final List<String> items = new CopyOnWriteArrayList<>();
}
Gotcha Enum in switch null Handling

Switch on null enum throws NullPointerException before reaching any case.

Status status = null;
switch (status) {  // NPE here, not inside
    case ACTIVE: ...
}

// Always null-check before switch
if (status != null) {
    switch (status) { ... }
}

Complete Example: Order State Machine for LLD

public enum OrderStatus {
    CREATED(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(PAYMENT_PENDING, CANCELLED);
        }
    },
    PAYMENT_PENDING(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(CONFIRMED, PAYMENT_FAILED, CANCELLED);
        }
    },
    PAYMENT_FAILED(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(PAYMENT_PENDING, CANCELLED);
        }
    },
    CONFIRMED(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(PREPARING, CANCELLED);
        }
    },
    PREPARING(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(READY_FOR_PICKUP);
        }
    },
    READY_FOR_PICKUP(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(OUT_FOR_DELIVERY);
        }
    },
    OUT_FOR_DELIVERY(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(DELIVERED, DELIVERY_FAILED);
        }
    },
    DELIVERED(true) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.noneOf(OrderStatus.class);
        }
    },
    DELIVERY_FAILED(false) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.of(OUT_FOR_DELIVERY, REFUNDED);
        }
    },
    CANCELLED(true) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.noneOf(OrderStatus.class);
        }
    },
    REFUNDED(true) {
        @Override
        public Set<OrderStatus> allowedTransitions() {
            return EnumSet.noneOf(OrderStatus.class);
        }
    };

    private final boolean terminal;

    OrderStatus(boolean terminal) {
        this.terminal = terminal;
    }

    public abstract Set<OrderStatus> allowedTransitions();

    public boolean isTerminal() {
        return terminal;
    }

    public boolean canTransitionTo(OrderStatus next) {
        return allowedTransitions().contains(next);
    }

    public OrderStatus transitionTo(OrderStatus next) {
        if (!canTransitionTo(next)) {
            throw new IllegalStateException(
                "Cannot transition from " + this + " to " + next);
        }
        return next;
    }
}

Interview Tips Checklist

  • Always use enums over string/int constants for type safety
  • Add behavior to enums—don't just use them as data holders
  • Use EnumSet for flags/permissions (show you know specialized collections)
  • Implement state machines directly in the enum
  • Cache values() array if iterating in hot paths
  • Prefer == over equals() for enum comparison
  • Use fromX() static factory methods for lookups
  • Keep enums focused—one enum per concept
  • Make fields final; enums should be immutable
  • Consider enum singleton for true singletons
